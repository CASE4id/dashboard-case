# PDF-to-dashboard data extraction toolkit

Python scripts that turn three statistical publications into clean, backend-ready CSV/XLSX files:

| Pipeline | Source | Output |
|---|---|---|
| `run_pln.sh` | *Statistik PLN* annual reports (2014–2025 configured) | `output/pln_statistics_<first>_<last>/` + zip — 10 tables per year, unit/province level, stacked across years |
| `run_bps.sh` | BPS *Statistik Gas 2020–2024* and *Statistik Transportasi Udara 2024* | `output/transmission_gas/` and `output/aerospace_air_transport/` + zips |

Each output folder has its own README, a data dictionary and `data_quality_notes.csv`.

## 0. In this repository: automatic run from GitHub (no local setup)

The workflow **Tambah data PLN dari PDF** (`.github/workflows/tambah-data-pln.yml`) runs the whole PLN pipeline on GitHub:
Actions tab → *Tambah data PLN dari PDF* → *Run workflow* → year + direct link to the PDF. It then:

1. downloads the PDF and, if `pln/config.json` has no entry for that year, builds one with **`pln/auto_config.py`**
   (pages found by table title; column layouts of earlier years and the toolkit's standard layout tried in turn; every candidate
   extracted and checked; year-specific fixes such as `relabel_rows` are never carried over);
2. runs `extract.py`, `validate.py`, `check_labels.py` and `combine.py` for that year;
3. writes the dashboard file `data/listrik/statistik-pln-<YEAR>.xlsx` with **`pln/to_dashboard.py`** (column order, unit list and
   dictionary from the previous year's dashboard file; quality notes from `pln/data_quality_notes.csv`);
4. writes a review report in Bahasa Indonesia with **`pln/laporan.py`** (national figures vs last year, check results, unit-list
   changes, unit-level jumps, the automatic layout table and, for tables that need review, the PDF's column headers next to
   last year's settings);
5. opens a pull request on branch `data-pln-<YEAR>`: a normal one when everything passes, a **draft** when something needs review,
   or a report-only draft (settings, no data file) when a table could not be read at all.

To fix a table that needs review: edit the `<YEAR>` entry in `pln/config.json` **on the pull-request branch** (see section 5),
then run the workflow again with *Use workflow from* = `data-pln-<YEAR>`. The pull request is updated, and marked ready when all
checks pass. A run from `main` refuses to overwrite an existing `data-pln-<YEAR>` branch.

The same steps run locally with `./otomatis_pln.sh <YEAR> <pdf-path-or-url>` from the repository checkout.
`PLN_ONLY_TABLES=t21 python3 pln/extract.py …` extracts only the listed tables (used by `auto_config.py`).

Tested on the 2014–2025 reports: the toolkit reproduces the dashboard data cell for cell. With each year treated as new,
`auto_config.py` finds the table pages every year and sets up all tables in years whose layout did not change; where PLN changed a
table's columns (2016–2021, 2024: Tables 2 and 21) it marks the table for review rather than guessing. Source-error fixes that are
caught: label swaps between Table 2 and Table 23 (e.g. 2025); not caught: footnoted cells in the wrong column (e.g. 2023 `cell_moves`).

## 1. Setup

```bash
# system tool (provides pdftotext/pdfinfo)
sudo apt install poppler-utils        # macOS: brew install poppler ; Windows: use WSL
pip install -r requirements.txt
```

Tested with Python 3.11, pandas 3.0, openpyxl 3.1, PyMuPDF 1.26 and poppler 24.02.

## 2. Put the PDFs in place

```
input/pln/Statistik2014.pdf … Statistik2025.pdf      # one file per year, this exact naming
input/bps/statistik_gas.pdf
input/bps/statistik_transportasi_udara.pdf
```

## 3. Run

```bash
./run_pln.sh               # all configured years that have a PDF
./run_pln.sh 2023 2024     # or selected years
./run_bps.sh
```

Running all 12 years takes about 25 seconds. The PLN run prints validation results for every year. Each `MISMATCH`/`COL` line is a total that doesn't add up. With the configured years, the only lines left are known errors in the source PDFs, all listed in `pln/data_quality_notes.csv`.

## 4. How the PLN pipeline works

```
PDF ──pdftotext/PyMuPDF──► page text + word positions
        │
        ├─ pln/config.json            which pages hold each table, and which columns each year's layout has
        ├─ pln/extract.py             parses rows, decodes fonts, pairs two-page tables, maps unit names
        │      └─ pln/unit_name_map.csv  (generated by pln/build_name_map.py) reported name → canonical unit
        ├─ pln/validate.py            row sums, unit→region sums, Table 1 vs Table 21, duplicate unit IDs
        ├─ pln/check_labels.py        cross-table label check (Table 2 vs Table 23 generation per unit)
        ├─ pln/check_trends.py        year-on-year spike/dip review list -> output/.../trend_review.csv
        └─ pln/combine.py             stacks years, derives missing totals, writes CSV/XLSX/README
```

Things `extract.py` handles, all learned from the 2014–2025 reports:

- **Number formats:** English `2,328.60`, Indonesian `2.328,60`, `183,808,97` (2016), and typos such as `3.00.00`. Values in brackets are negative and `-` means empty.
- **Shifted-font encodings:** some 2015 and 2018 pages store text 29 code points low (`*HQHUDWLRQ` = "Generation"). Affected segments are decoded automatically.
- **Two-page tables:** rows are paired by vertical position, falling back to order, so blank or split rows on one page don't shift the other.
- **Blank cells, wrapped names, values printed on the line below their name, rows with only a few values:** placed in the right column using word positions.
- **Bilingual overlay (2014 network tables):** only the English text layer is read.
- **Unit renames across 12 years:** handled in `build_name_map.py`, for example "Region of Aceh" → "UIW Aceh" → "UID Aceh" all become `uid_aceh`.
- **Documented source fixes,** set per year in `config.json`:
  - `token_fix` replaces a misprinted value (e.g. `"6-"` → `"60.00"`).
  - `cell_moves` moves a footnoted value to its proper column.
  - `null_cols` blanks a column that is unusable in the source.
  - `relabel_rows` corrects row labels that are printed against the wrong figures, by row position. This was needed for 2014, 2022 and 2025 Table 2, where the right labels were established from Tables 1, 21 and 23.

### Quality checks (what each one catches)

| Check | Catches | Blind spot |
|---|---|---|
| Row sums, units → region sums (`validate.py`) | Misread numbers, wrong column order, dropped rows | Labels printed against the wrong figures (the sums are unchanged) |
| Table 1 vs Table 21 per unit | Misaligned capacity rows | Errors that are the same in both tables |
| Duplicate `unit_id` (`validate.py`) | Two rows mapped to one unit | — |
| Table 2 vs Table 23 per unit (`check_labels.py`) | Label shifts and swaps in the energy tables | Tables with no counterpart (e.g. SAIDI, line lengths) |
| Spike/dip review (`check_trends.py`) | Remaining label swaps, implausible values in any table | Writes a list for a person to check; it decides nothing |
| **Manual spot check** | Anything the automatic checks can't see | — |

Recommended sign-off for each new year: run the pipeline, resolve every MISMATCH line, then check every `trend_review.csv` row for that year against the PDF, plus 10 random cells. Record the result in the `checked_against_pdf` / `outcome` columns.

## 5. Adding a new PLN year

1. Find the pages: `python3 pln/tools/find_tables.py input/pln/Statistik2026.pdf`. This lists the pages that contain unit tables and the table titles found on them.
2. Check the layout: `python3 pln/tools/count_columns.py input/pln/Statistik2026.pdf 17,18,19,…` gives the number of values in the Aceh/Indonesia rows on each page.
3. Add a `"2026"` entry to `pln/config.json`. Copy the most similar year and adjust:
   - `pages` for each table;
   - `split`, the number of columns on the left-hand page, for tables that span two pages;
   - `keys`, the column order, only if it differs from the standard schema. All possible columns are defined in `extract.py` (`T[...]["cols"]`).
4. Run `./run_pln.sh 2026` and read the validation lines.
   - A row-sum or column-sum mismatch usually means the column order or `split` is wrong.
   - A `duplicate unit_id` line or a `label shift?` line means two rows map to the same unit, or a row's figures belong to another unit. Compare with the other tables and fix it with `relabel_rows` or a name variant.
   - A unit that appears only in the new year usually needs a name variant added to `pln/build_name_map.py`.
5. Add any genuine source errors to `pln/data_quality_notes.csv`, then run `./run_pln.sh` for all years to rebuild the combined package.

## 6. BPS pipeline notes

- **Gas (`bps/bps_gas.py`):** the 10 gas tables are small and the text layer is broken up by the "bps.go.id" watermark, so their values are **transcribed into the script** and checked against the published totals when it runs. For a new edition, update the numbers in `bps_gas.py` and re-run; the totals check will catch typos.
- **Aviation:**
  - **National Tables 3.1–3.9:** transcribed in `bps/bps_build_air.py`. These were checked against the rendered pages, because the watermark corrupts a few numbers in the text layer.
  - **Airport appendices:** parsed directly from the PDF by `bps/bps_airport.py`. It checks that airports add up to province subtotals and provinces to the national total. The page ranges in `run_bps.sh` are for the 2024 edition; update them for another edition.
